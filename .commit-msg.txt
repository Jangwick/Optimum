fix: robust entrypoint script with env var debugging

The Railway MySQL addon variables were not being injected into the
app service. The previous inline CMD fallback was not finding any
MySQL variables either.

Created server/entrypoint.sh which:
- Prints all available MySQL/DATABASE env vars at startup for debugging
- Tries DATABASE_URL, MYSQL_URL, MYSQL_PRIVATE_URL, and individual
  MYSQLHOST/MYSQLUSER/etc variables
- Prints a clear error with all env vars if nothing is found
- Runs prisma migrate deploy, db seed, then starts the server

This will show exactly what variables Railway is injecting, making
it easy to identify the correct variable name to use.
